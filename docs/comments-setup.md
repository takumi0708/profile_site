# 追加機能のセットアップ

## データベース

Supabase SQL Editorで `supabase/migrations/202609200002_comments_tags.sql` を一度実行してください。
既存の初期SQLは再実行しません。追加SQLは既存の質問・回答を維持して、自由なカテゴリ、タグ、閲覧者コメントを追加します。

管理画面から質問・Projects・コメントを削除できます。削除した投稿のコメントも削除されます。
子質問は削除せず、親との関連だけ解除します。

## コメント受付

`.env.local` の `SUPABASE_SERVICE_ROLE_KEY` にSupabaseのサーバー専用キー（service_roleまたはSecret key）を設定してください。
ブラウザ向けのPublishable keyとは別です。`NEXT_PUBLIC_`を付けず、Gitにコミットしません。
サーバーのみが投稿用DB関数を呼び出せます。公開中の投稿へのコメントだけを受け付けます。
受付直後は非公開です。管理者が回答し公開チェックを入れると、投稿元の詳細ページに質問と回答が表示されます。

## メール通知（Resend）

閲覧者が質問・コメントを送った場合だけ、通知メールを送ります。管理者の投稿・編集・回答では送りません。

1. ResendでAPIキーを作成して `RESEND_API_KEY` に設定します。
2. `NOTIFICATION_EMAIL` に通知先を設定します（ローカルには指定済み）。
3. `NOTIFICATION_FROM` にResendで利用可能な送信元を設定します。
   本番では認証済みドメインのアドレスを利用してください。
4. 開発サーバーを再起動します。本番環境にも同じ環境変数を設定してください。

[Resend送信API](https://resend.com/docs/api-reference/emails/send-email)を使用しています。
通知が失敗・未設定の場合もコメントは保存されます。管理画面に「メール未送信」と表示し、設定後に再送できます。
自動定期再送ではありません。APIが受理した時点で通知済みとします。受信箱への到達は実メールで確認してください。
同じコメントの再送にはResendのIdempotency-Keyを利用しますが、その保持期間を超えた再送では重複の可能性があります。

## 投稿制限

さらに `supabase/migrations/202609200003_comment_spam_limits.sql` を一度実行すると、
同じ投稿への同文コメントを24時間拒否し、サイト全体の受付を1時間20件・24時間100件に制限します。
時間枠は最初の受付時点から数えます。コメントを削除しても全体件数はリセットされません。
上限到達時は正常な閲覧者も投稿できなくなります。これは保存件数・通知数の上限であり、
リクエスト自体の大量送信を防ぐものではありません。

DBで10分に3件に制限し、同時リクエストでも制限します。Vercelではプラットフォームが設定する
`x-vercel-forwarded-for`を利用し、IPをHMACで変換して制限に利用します。生IPは保存しません。
その他の環境・ローカルでは共通枠で10分に3件です。別のホストでは信頼できるプロキシのIP取得方式に合わせて変更してください。
24時間以上古い制限情報は次の正常投稿時に削除します。

## 確認

- `npm run lint` / `npm run build`
- `node --test tests/comments.test.mjs`（実際のSupabaseに変更を加えないローカルPostgreSQLテスト）
- `node --conditions=react-server --test tests/notifications.test.mjs`（実メールを送らない通知テスト）
- 管理画面でタグ・自由カテゴリの保存、削除確認チェックを付けて削除
- ログアウトしたブラウザでQ&A／Projectsの詳細からコメント投稿
- 管理画面でコメント受信・通知メールを確認
- 回答を入力して公開 → 詳細に表示 → 非公開に戻すと消えることを確認
- 管理者による投稿・編集で通知メールが届かないことを確認
